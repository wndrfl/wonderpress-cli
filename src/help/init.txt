wonderpress init — build a new environment

Clones the Wonderpress development environment, downloads WordPress, creates
the database, installs the theme's Composer dependencies (chiefly
wonderpress-core) and Static Kit, and activates the theme.

ENVIRONMENT BACKENDS
  host (default)  WordPress and MySQL on this machine, served by `wp server`.
                  Needs a running MySQL.
  wp-env          WordPress, MariaDB and a pinned PHP 8.2 in Docker, with the
                  project mounted in. Needs Docker running. Already serving
                  when init finishes — there is no `wp server` step.

  The backend is recorded in .wonderpressrc, so --env is only needed when
  building. Both still need wp-cli, php and composer on PATH: wp-env replaces
  MySQL, not the PHP toolchain. Set WONDERPRESS_ENV to override per-invocation.

  `wonderpress doctor` runs init's prerequisite checks on their own, before
  anything is built.

  Windows: use wp-env (Docker Desktop with the WSL2 engine). The host backend
  is not supported there; init warns ("it may work, but nothing tests it
  there") and carries on rather than refusing. macOS and Linux support both.

  init pins the running CLI version as `cliVersion` in .wonderpressrc (unless
  the project already pins one). Commit it: any other CLI version warns when
  run in this project.

  --namespace is written into page content as <namespace>/<slug>. Change it
  later and existing blocks become unrecognized. Pin it at init; it is stored
  in .wonderpressrc and does not drift.

OPTIONS
  --dir <path>             Where to build it (default: current directory)
  --env <backend>          host (default) or wp-env
  --yes, -y                Headless: take defaults and never prompt
  --db-host / --db-user / --db-name / --db-password
                           Database connection. Password may also come from the
                           WP_DB_PASSWORD environment variable. Host backend
                           only — wp-env fixes its own database.
  --wp-url <url>           Site URL, e.g. localhost:8080. Host backend only —
                           wp-env serves on the port in .wp-env.json.
  --wp-title <title>       Site title
  --admin-user / --admin-email / --admin-password
                           The first admin account. Password may also come from
                           WP_ADMIN_PASSWORD. --admin-user is refused on
                           wp-env (the first user is always `admin`).
  --theme <name>           Theme to activate (default: wonderpress)
  --namespace <slug>       Block namespace for this project. Defaults to the
                           theme slug. Set once.
  --skip-readme            Do not generate a README
  --readme                 With --yes, generate a README named after the title
  --format json            With --yes: progress events, then one envelope (below)

JSON PROGRESS (--yes --format json)
  stdout is newline-delimited JSON; every human line goes to stderr. One event
  when each step starts and one when it ends, then one final envelope:

    {"event":"step","id":"scaffold","label":"Clone the environment scaffold","state":"running"}
    {"event":"step","id":"scaffold","state":"done"}
    {"event":"step","id":"wordpress","state":"failed","error":{"code","message","hint"}}
    {"ok":true,"data":{"root","backend","theme","namespace","cliVersion","url",
      "steps":[{"id","state","ms"}]},"error":null}

  Steps, in order: scaffold, assets (Static Kit), wordpress (prepare and
  provision), core (Composer, wonderpress-core), theme (activate, README).
  States: running, done, failed (queued is implied). Nothing runs after a
  failed step. A failed preflight is the envelope alone, error code
  "preflight". It never prompts: without --yes it is a "usage" error, and
  several themes with no --theme is a "usage" error naming the flag.
  SIGINT/SIGTERM stops the current step and its child processes, prints the
  envelope with error code "cancelled", exits non-zero, and deletes nothing
  (a cancel during the --clean-slate teardown stops before the wipe). An
  error outside every step is still one envelope, error code "init".

EXAMPLES
  wonderpress init --yes --db-user root --db-name my_site \
    --wp-url localhost:8080 --wp-title "My Site" \
    --admin-user admin --admin-email me@example.com

  wonderpress init --env wp-env --yes --wp-title "My Site" --namespace acme

  wonderpress init --env wp-env --yes --format json --namespace acme
