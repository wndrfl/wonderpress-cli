wonderpress doctor — check this machine's prerequisites

Runs the checks `init` runs before building anything — WP-CLI and Composer
for the host backend; Docker, Compose v2, a live Docker daemon, WP-CLI,
Composer and a free port for wp-env — and reports them in one place. Prints failures only, each with how to
fix it, then a one-line summary. Exits 1 when anything fails.

Which checks run:
  inside a project         that project's backend (from .wonderpressrc)
  --env <backend>          that backend
  outside a project        every backend

The host backend is not supported on Windows; there it reports one failing
check saying to use wp-env instead. (`init` only warns about it and carries
on — it may work, but nothing tests it there.)

A port conflict names the platform's own way to see what holds the port:
lsof on macOS, ss on Linux, Get-NetTCPConnection or netstat on Windows.

Inside a project, one project-level check joins the machine-level ones:
`core-record`, whether the wonderpress-core version .wonderpressrc records
is the one the theme's composer.lock resolves. It fails after a bare
`composer update` in the theme; `wonderpress core update` repairs it.

OPTIONS
  --env <host|wp-env>      Check one backend
  --dir <path>             Project root
  --format json            data: { backend, platform, ok, checks: [{ check,
                           label, ok, backend, platform, hint, detail }] }.
                           `backend` is null when every backend was checked.
                           A failing run is ok:false with the same data.

EXAMPLES
  wonderpress doctor
  wonderpress doctor --env wp-env
  wonderpress doctor --format json
