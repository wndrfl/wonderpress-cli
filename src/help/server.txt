wonderpress server — local development environment

Starts the site for whichever backend this project was built with (recorded
in .wonderpressrc). Bare `wonderpress server` means start.

On host, start blocks in the foreground until Ctrl-C. On wp-env, it brings
the Docker environment up and returns.

COMMANDS
  server                   Start the environment (same as `server start`)
  server start             Start
  server stop              Stop (wp-env). The host server is stopped with
                           Ctrl-C in the terminal that started it.
  server status            Is it running, and where? Works from any terminal:
                           wp-env is asked directly, the host is probed by
                           connecting to its port.

OPTIONS
  --dir <path>             Environment root
  --format json            One { ok, data, error } envelope on stdout. data:
                           { backend, detached, running, url, adminUrl, port,
                           pid }. `running` is true, false, or null when it
                           could not be told (on wp-env, something holds the
                           port but wp-env could not confirm it is this
                           project's); url/adminUrl/port are where the
                           site is served whether or not it is up.

  On host, `start --format json` prints the envelope once the site answers,
  then keeps serving; `wp server`'s own output goes to stderr, so stdout holds
  the envelope and nothing else. `pid` is that server's process id, and it
  leads a process group holding `wp server` and the `php -S` it runs. To stop
  it, send SIGINT/SIGTERM/SIGHUP to the `wonderpress server start` process
  (it forwards them to the group and exits 0), or `kill -TERM -<pid>`. If the
  server dies on its own after the envelope went out, that process says so on
  stderr and exits 1.

EXAMPLES
  wonderpress server
  wonderpress server status
  wonderpress server status --format json
  wonderpress server stop
